# Search

Open **Search Tavern** from the quick switcher, or type a query in the switcher and choose **Search Tavern for …**. The same panel finds indexed messages and files, people already loaded in shared rooms, and joined channels, conversations and servers. Use **Find** to choose a result type and **Within** to limit results to the current conversation.

People open their profile in an actual shared room. Places use ordinary Tavern navigation, including private discussions. Message results open the original native message. File results first resolve that message again, then use Tavern's existing authenticated attachment preview and download; an indexed filename is never treated as a media URL or permission to download a different file.

Messages and files support `from:username`, `in:channel`, `before:YYYY-MM-DD`, `after:YYYY-MM-DD`, `has:image`, `has:file`, `has:link`, `mentions:me`, and quoted phrases. Filename components and MIME types are searchable, including a filename that differs from its message caption. Message operators apply to history results, not to the people/place inventory. People and places use the quick switcher's fuzzy matching.

Search does not fetch a user directory, missing room members or message history just because the panel opens. It uses at most 2,000 joined rooms and 5,000 loaded member entries for the people/place inventory, showing a partial-coverage notice when that bound is reached. Those results are paged in groups of 20. Indexed history queries return up to 30 matches and examine at most 2,000 candidate records per page; **More messages and files** continues the indexed query. Typing and reaction updates do not cancel a pending query or reset pages already loaded. Use **Refresh results** to rebuild the current inventory and query deliberately. Account, device, current room identity, membership and ignored-user checks still apply while results are displayed and when they are selected.

Expand **History coverage and search privacy** to index older history in the selected conversation. Each explicit run fetches at most 20 pages of 100 events. A continuation is offered when older history remains. Cancellation keeps completed index records. Empty advancing history pages are followed; a repeating or malformed cursor is an error, not proof that the history is complete. Reaching the start describes only history available to the current account. Missing encryption keys, removed messages, hidden history and uncached members prevent a global completeness claim.

Bodies and file metadata are stored in the existing device-specific IndexedDB index under AES-GCM encryption. Search postings are keyed HMAC values. The stored metadata adds filename, MIME type, media kind and optional byte size; it does not copy attachment decryption keys, download URLs, thumbnails or file bytes into search records. Room/event identifiers and chronological index fields remain outside the ciphertext as in the existing local index. Old encrypted records remain readable; records without separate file metadata gain it when their messages are indexed again. No history is downloaded solely to migrate those records.

Search is bound to the active Matrix account, device and managed API-session generation. Queued indexing and awaited queries reject stale ownership, and room replacement or departure prevents a late result from being shown. An open search preview closes and revokes its object URL when its account or room scope is no longer current. Clearing the local index does not change homeserver messages.

Validation uses the real browser IndexedDB and WebCrypto implementation for encrypted metadata, filename postings, history pagination and the unified panel. Native event lookup, file transport and Matrix sync are bounded fixtures in these browser tests; they do not claim a new live homeserver encryption acceptance result.
