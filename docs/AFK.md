# AFK voice settings

Open server customization and use **AFK voice channel** to choose an encrypted voice channel and a timeout of 5, 10, 15, 30, or 60 minutes. The destination must be an available, unarchived voice channel with reciprocal links to the server. Editing requires current server membership, native state permission, and the server's `manage_server` permission when a role policy is present. Choose **Disabled** to remove the suggestion.

Members can opt in separately while each conference is active. The checkbox leaves that conference after no keyboard, pointer, wheel, or touch interaction in the Tavern tab or its embedded call frame. A 30-second warning includes **Stay in conference**. After leaving, **Open AFK channel** opens the destination; the member decides whether to join another call. The checkbox resets for a new call, account, or changed server configuration. Calls in the AFK destination do not trigger another handoff. Ambiguous multiple-parent channels do not inherit an AFK suggestion.

This is local interaction idle handling. Speech, listening, screen sharing, and activity in other tabs or applications are not measured. Suspended browsers can delay timers; a first timer callback after suspension gives a fresh warning interval. No media is captured to detect activity. Server configuration uses native Matrix state, revision checks, and server-side destination validation. Membership and permissions continue to control all access. Changing the setting does not move members or grant access to its destination.

Tavern's pinned Element Call embedded package, version 0.25.0, registers join, hangup, and device-mute widget actions. Tavern binds its widget bridge to one room and uses its existing cleanup to leave. There is no room-transfer action exposed by this integration. Starting a destination call would create another session and may request devices again, so AFK handling does not start one automatically. The upstream [widget URL documentation](https://github.com/element-hq/element-call/blob/main/docs/url_params.md) describes the room binding and the separate `autoLeave` setting for an empty call; that setting does not detect inactivity.

Focused tests cover the server settings form and state revision, current permissions, invalid destinations, redaction protection, stale edits, account changes, warning/reset/expiry behavior, trusted interaction inside the iframe, and no capture requests from the inactivity controls. A real multi-user TURN/LiveKit session is still needed to validate idle disconnect across deployed network conditions; the focused browser fixture does not replace that acceptance test.
