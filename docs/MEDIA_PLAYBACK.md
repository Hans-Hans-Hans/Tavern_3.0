# Media playback and previews

The attachment viewer uses Tavern controls for video playback, seeking, volume, speed, fullscreen and Picture-in-Picture. Space or K toggles playback, M toggles mute, and left/right seek five seconds when the player itself has focus. Sliders retain their native keyboard controls. Escape closes the viewer. Unsupported presentation features are disabled; decoding failures offer the existing file download path.

The viewer downloads and decrypts an attachment once. Its Download link reuses that local blob, preserving the original bytes. Changing attachments or closing the viewer pauses playback, exits owned presentation modes, stops reads and releases object URLs. Account changes cannot complete an old attachment download, including a change during decryption. Download bodies are checked against both declared and streamed size limits, and encrypted attachment integrity is verified before display.

Uploads follow the [administrator-controlled file size](UPLOAD_LIMITS.md), defaulting to 10 MiB and supporting up to 512 MiB. Automatic previews retain their 20 MiB bound; explicit downloads support the larger files. Supported local MP4, WebM and Ogg videos can supply a first-frame WebP poster, dimensions and a duration when the browser reports one. Poster extraction has a five-second deadline, a 40-million-pixel source bound and a 480×320 output bound. Posters are at most 512 KiB and use the existing separately encrypted thumbnail upload. Failure to decode a preview leaves the original upload usable. No server video processing or plaintext media inspection is added.

Local verification uses a generated 1,330-byte VP8 WebM fixture, real browser decoding/playback, byte-for-byte downloaded-file comparison, phone viewport controls, native fullscreen/Picture-in-Picture, invalid-file handling and object-URL cleanup. The fixture generator is [generate-video-fixture.mjs](../scripts/generate-video-fixture.mjs); it packages synthetic canvas frames according to the [WebM container format](https://www.webmproject.org/docs/container/). These checks do not establish every codec or mobile-device combination. Broader MP4/Ogg/device acceptance remains necessary.
