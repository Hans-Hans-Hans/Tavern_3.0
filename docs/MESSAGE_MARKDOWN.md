# Message Markdown

Tavern renders ordinary message Markdown in channel, direct-message, thread, private-discussion and opened forum conversations, and in local search results. Formatting includes headings, emphasis, nested lists, blockquotes, strikethrough, tables, line breaks, explicit links, inline code and fenced code. Escapes and reference links follow the pinned Markdown parser. Forum cards and forwarding dialogs retain short plain-text previews.

The parser is `markdown-it` 15.0.1, pinned in the package lock. HTML is disabled, and Tavern converts its tokens into a fixed set of React elements; it never inserts user HTML. See the [pinned release](https://github.com/markdown-it/markdown-it/releases/tag/15.0.1) and [parser options](https://markdown-it.github.io/markdown-it/interfaces/MarkdownItOptions.html).

Only credential-free, explicit HTTP and HTTPS destinations become navigable links. Bare domains, email addresses, relative paths and other schemes remain text. Markdown images become labeled links; rendering a message does not load those remote images, audio, video or embedded frames. Explicitly opening a link still contacts its destination. Valid Tavern role-mention tokens render an inert label; the renderer does not grant mention authority or navigate to a custom URI.

`||spoiler text||` starts hidden and can contain inline formatting, links and server emoji. Revealed content resets when the message is edited. Spoilers in link labels keep their reveal control and suppress the enclosing link, avoiding nested interactive elements. Markdown code remains literal: emoji, mentions and spoiler markers inside code are not expanded. Code blocks have basic token highlighting and copy the exact parsed code body, with a visible recovery message if clipboard access fails; code is never executed.

Optional preview buttons use the same parsed visible links, excluding spoilers, code and collapsed plain-text fallbacks. Hidden destinations therefore do not disclose their domains in preview controls. Preview fetching still requires a click and server-side URL checks. Every message edit discards prior preview consent and results; late responses are ignored after an edit, unmount or account change. At most three distinct visible links offer a preview.

Parsing is limited to 32,000 UTF-16 source units, 4,096 converted tokens and 20 levels of nesting. Unsupported or excessive formatting uses a collapsed plain-text view. Oversized messages offer a clearly labeled shortened plain-text view, without cutting an emoji surrogate pair. Users explicitly expand these fallbacks, so a formatting-limit failure does not automatically reveal spoiler text. These display limits do not alter the stored message.

Focused tests exercise actual parser output, hostile markup and schemes, nesting, code payloads, spoiled content, role tokens, pathological inputs and size limits. Browser tests exercise the actual Tavern formatting expression with server emoji, search-result keyboard navigation, code-copy failure, spoiler reset, and mobile overflow. The browser media boundary is stubbed; these checks do not claim a live Matrix media download or delivery test.
