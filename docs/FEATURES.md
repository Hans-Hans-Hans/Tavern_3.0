# Tavern feature coverage — 0.4 development

Tavern keeps the existing Matrix architecture for encrypted messaging and builds community, account, and administration features around it. The [130-section implementation checklist](IMPLEMENTATION_CHECKLIST.md) records each requested area, source evidence, and remaining work. “Implemented” describes a code path; deployment and interoperability claims require the separate [validation record](VALIDATION.md).

| Area | Implemented | Remaining or deliberately limited scope |
|---|---|---|
| Accounts | One-time verified administrator bootstrap; username/email login; email recovery; TOTP/email MFA and recovery codes; cookie sessions; device revocation; required password changes | External identity providers, passkeys and platform authority beyond administrator/user |
| Profiles and contacts | Optimized avatar/banner crop, pronouns/bio/fields/timezone/status, per-server profile, presence modes, durable friend requests and server-enforced invitation privacy | Original join dates when historical metadata is unavailable; remote/unavailable account dates are shown as unknown; per-server invitation preferences |
| Servers and channels | Matrix Spaces, categories and ordering, branding, favorites/folders, channel types, private membership, archive/slow mode, welcome/interest recommendations and welcome/rules links, creation/server/channel notification defaults | Full historical discovery, optional interest-based role assignment, system-message routing, AFK and content/verification defaults |
| Roles and permissions | Multiple roles, fast member assignment, invitation default grants, hierarchy, icons/colors/grouping, role/member category inheritance and channel overrides; authorized server nicknames and channel webhook management; authoritative Synapse module checks | Matrix native membership/power remains an additional ceiling. A server cannot enforce encrypted attachment/link subtypes without decrypting them |
| Messages | Configurable inline editing, optimistic reactions with member popovers, reply/thread/quote/mentions, Markdown/code/spoilers, pins/bookmarks, deep links/unread markers, forwarding with destination reencryption, consent-based link previews | Full rich-text format coverage and independent multi-device acceptance |
| Threads and forums | Virtualized replies, paged forum cards, explicit historical paging from empty results, status filters/reactions, participant list, notifications, title/tags/lock/archive and server-time inactivity archive | Private thread membership and complete historical forum indexing |
| Files and media | Encrypted uploads/downloads and image thumbnails, integrity checks, progress/cancel/retry, per-user/global byte quotas, authenticated media viewer with zoom/navigation/save/open original | Per-server quotas, resumable upload, encrypted-content classification, dedicated video editing/transcoding |
| Search and navigation | Device-local encrypted IndexedDB search with keyed term index, filters/operators, opt-in cancellable history indexing, quick switcher and command palette | Indexed scope is the decrypted history on this device. No server plaintext search or automatic complete historical coverage |
| Offline work | Encrypted local outbox, scheduled sends and reminders with retry/edit/cancel; per-conversation memory drafts and channel draft badges | The owning signed-in device must run to send scheduled work. Outbox/reminders do not sync across devices |
| Calls | Direct voice/video/screen share, device controls, echo/noise/gain, push-to-talk/deafen, per-user local volume, native fullscreen/PiP, measured speaking and connection statistics; MatrixRTC/LiveKit conferences and persistent dock | External-network/device acceptance and independent server mute/deafen/move controls |
| Call moderation | Verified participant identity and authorized removal of channel membership plus matching active LiveKit devices, with partial failures reported | Independent server mute/deafen and move-between-channel actions |
| Collaboration | Encrypted tasks, authored notes, events/calendar export, single/multiple-choice polls with expiry and visible editable votes | Anonymous polls, shared-document editing and complete historical work indexing |
| Notifications and appearance | Synced global/server/channel/thread overrides, timed mutes, DND, generic desktop/message/friend-request/incoming-call alerts and optional sound; system/light/dark themes, fonts/scale/motion/saturation | Closed-browser/mobile push, full accessibility and contrast acceptance |
| Administration | Real user/session/room/storage/status data; user filters/sort/details/security actions; registration/maintenance/announcements; private platform reports and explicitly shared room-moderator reports; staff resend-email verification; filtered account/server audit; private warnings, temporary bans, bulk redaction, branding/security policies and measured logs/CPU/memory/queue data; SMTP and integration administration | Platform voice/WebSocket telemetry and anonymization/retention policy |
| Data export | Account/settings/warnings metadata and streaming decrypted historical JSONL export | Device keys and current history access determine available messages; bounded fallback download and explicit plaintext consent |
| Integrations | Signed webhook ingestion, durable encrypted bot delivery, room/user/device allowlists, secret rotation/revocation, name/avatar/enabled/creator metadata, authorized channel management and independently verified device approvals | Destinations stay bound to their original room; moving requires a new hook/token. One-time bot identity provisioning remains an operator task. OAuth app catalog and arbitrary automation are absent |
| Operations | Canonical Compose with generated persistent configuration, named volumes, health checks, backup/download/retention, isolated-copy restore and compatible web/API patch updates | Production restore cutover and infrastructure/schema upgrades remain explicit operator procedures; final restore/upgrade acceptance must be recorded |
| PWA | Install manifest/icons, versioned static-shell cache, offline/reconnect UI, all-tab active-crypto/media update guards | Android/iOS installation and device-specific offline/update acceptance |

New encrypted rooms keep message content and attachments end-to-end encrypted. Profiles, room state, membership, timing, and ordinary preference metadata remain visible to the homeserver. Administrative features do not decrypt arbitrary user conversations. Recovery preserves existing encryption identity and backup versions; it does not silently replace keys to clear an error.

Observed builds, browser/API tests, container checks, and outstanding live acceptance are tracked in [VALIDATION.md](VALIDATION.md). This table is not a claim of complete Discord, Slack, or Teams parity.
