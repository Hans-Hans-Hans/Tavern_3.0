# Inspecting server and channel relationships

Open **Administration → Rooms → Inspect**. The **Server and channel hierarchy** section reads the selected room's native metadata and a page of its declared Space relationships. Expand a confirmed link to inspect its next level, or choose **Inspect** to open that room's administration dialog. Existing member inspection and typed block/unblock confirmation remain available.

Only a native homeserver administrator can use this endpoint. It does not join the administrator to a room. Native administration is checked before inspection and again before returning data; the browser discards results when its account session or selected room changes.

A confirmed edge needs a real `m.space` parent, a nonempty valid `m.space.child` link on that parent, and a matching `m.space.parent` link on the child. Noncanonical reciprocal parent links are still native structural relationships; their presence does not establish Tavern role inheritance or moderation authority. One-way, malformed, missing and unreadable links are reported separately. A self-link is reported as a cycle. The browser stops expansion when a room is already on that path, including the normal reciprocal reference back to its parent.

The metadata projection includes the native name, room version, create-event timestamp when present, joined membership count, native creator identities, encryption and join policy, archive state when present, and a valid replacement-room reference. Version 12 creator identities come from the create-event sender and `additional_creators`, whose inherent authority does not depend on the power-level `users` map. Other room versions label creators separately from current power-level authority. Creator identity is not a claim that an account still has a particular Tavern custom role. Unknown creation time and archive state remain unavailable.

Room storage totals and message activity are explicitly unavailable here. The inspector returns no message history, full room-state events, member profiles, file contents or media decryption keys. Instance storage usage remains in the separate Storage view with its existing scope description.

Each relationship page checks at most 20 candidates, from at most the first 200 valid room identifiers in a node's native links. A native state read is limited to 1 MiB and 10,000 events, with three reads at a time, a three-second read deadline and a twelve-second deadline for the whole request, including administrator checks. Exceeding a room-state limit produces an unavailable node; exceeding the page deadline produces a retryable error. No unbounded background traversal runs. The UI stops at eight levels and 100 displayed room entries. Inspect a nested room separately to continue beyond the view limit. A room with more than 200 relationship candidates remains explicitly partial.

Later pages supply the selected node's relationship revision. The API rejects a changed source revision and rechecks that source after reading counterparts, so it does not silently combine pages from different source state. Counterpart metadata is read during that page, not in a cross-room atomic snapshot; names, membership and relationships can change after the checks. Reload a node to obtain a new view. Reload also drops its expanded descendants and ignores their late results.

Validation covers actual aiohttp administrator/ordinary-account requests, native version 12 create semantics, malformed and foreign state, reciprocal links and cycles, changed source revisions, session/admin revocation, byte/event/page/concurrency/deadline limits, and existing room block behavior. Browser coverage mounts the real administrator Rooms navigation, keyboard and small-screen hierarchy controls, pagination, display limits and delayed room/account results. The native HTTP boundary is a fixture in these local checks; no live homeserver acceptance is implied.
