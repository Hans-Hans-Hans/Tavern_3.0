# Embedded conference telemetry

Tavern observes the existing Element Call 0.25.0 call view and LiveKit tracks to display connected participants, speaking activity, media encryption observations, and measured audio quality. It does not create a second call, capture stream, WebRTC connection, or stats upload.

The roster uses Element Call's Matrix-to-LiveKit member binding, matched to current joined Matrix members and connected backend identities. Unattested SFU participants are excluded. Names and avatar references come from current Matrix room members. The display is limited to 128 entries and marks a larger roster as partial. It is a current observation, not an admission decision or a complete historical attendance list.

Room E2EE configuration and each participant's observed publication encryption flags are separate observations. Missing observations stay unknown; an explicitly unencrypted publication must not be displayed as encrypted merely because the room enables E2EE. These flags do not independently attest a remote device's behavior or prove that every media packet decrypted successfully.

RTT and jitter are milliseconds from the existing audio tracks' RTC statistics; packet loss uses successive received/lost packet counters where available. RTT is a media-path measurement, not a separate homeserver ping. Each displayed metric is the largest valid measurement among at most eight sampled microphone tracks. Sampling occurs every two seconds, with a 1.5-second wait limit, at most 512 report entries per track, and bounded counter retention. A stalled native stats call is shared across later ticks rather than duplicated. Missing samples remain unavailable. Raw reports, network addresses, ICE candidates, credentials, and encryption keys never enter telemetry messages.

The parent receiver accepts only the mounted iframe window, exact origin, room, widget identity, and per-mount nonce. A fresh challenge is delivered to the current document after iframe load or bridge initialization, allowing safe sequence restart after reload. Old document messages, old owners, and reordered messages are rejected. The roster becomes unavailable after five seconds without a valid update and clears on owner loss or disposal. Native member, participant, connection, and track replacements invalidate pending samples. All added observers and timers belong to the existing call lifecycle.

An error from the active call view's `fatalError$` is sent immediately, before its scope tears down. The diagnostic contains only an allowlisted Element Call code, cause category, HTTP status, LiveKit reason, and Matrix error code; unknown values are omitted or classified as unknown. Raw messages, stacks, localized text, URLs, and request contents are excluded. The first observed fatal descriptor remains available until session disposal; stale participant and quality data are cleared. Errors from retired connection views are not used. This hook observes the active call model: a separate React render error caught directly by its error boundary may not enter that model and is not claimed to be captured.

Voice mode uses Element Call's supported `start_call_voice` intent: initial video is disabled before device state is created. The parent voice iframe also excludes camera and display-capture permission. Ordinary conference mode retains its existing media controls.

`scripts/prepare-call-assets.mjs` verifies the pinned package, asset, and source-map hashes, then applies one AST-identified call-view return hook through `scripts/transform-call-telemetry.mjs`. An upstream change stops preparation until reviewed. Composed source maps preserve corresponding upstream source; the added bridge sources and original license files accompany the generated assets. `public/element-call/SOURCE.txt` records upstream revision and the reproducible modifications.

Local validation covers the actual pinned source transformation and source mapping, supported voice intent, observable lifecycle, bounded synthetic RTC reports, actual pinned error-class projection, immediate active-failure delivery, strict message parsing, and five real iframe receiver tests including reload, account replacement, and stale diagnostic retention. These checks do not replace live multi-device MatrixRTC and media acceptance.
